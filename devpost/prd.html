4. Features, Acceptance Criteria & Product Decisions

Feature 1: Session Lifecycle & State Protection (`commitgate start` / `cancel`)
  • commitgate start --task "Fix login validation" --require "src/auth/**" --test "npm test" --token "CG-001" creates an active session in commitgate.db with status PENDING.
  • Refuses to overwrite an active session unless --replace is passed (marks old session SUPERSEDED) or commitgate cancel CG-001 is run (marks CANCELED).
Feature 2: Automatic Git `post-commit` Hook & 4-Rule Deterministic Verifier
  • Rule 1 (Token): Commit message contains session token (CG-001).
  • Rule 2 (Required Path): Changed files match --require glob (src/auth/**).
  • Rule 3 (Meaningful Code Change): Matched file has > 0 non-whitespace changed lines (full comment-only AST parsing deferred to Later).
  • Rule 4 (Tests Passed): --test command (npm test) exits with code 0; on failure, captures last 5 lines of output.
Feature 3: Non-Intrusive Edge Cases & Boundaries
  • Commits When Idle: Never blocks normal Git work; prints CommitGate: no active session. Commit ignored. and records UNTRACKED in SQLite.
  • Rejected Attempt Handling: Surfaces REJECTED in red on the HUD and terminal with specific failure diagnostics while keeping session CG-001 active for the next commit.
