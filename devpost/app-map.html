CommitGate (`commitgate`) — App Map

Take-home architecture guide connecting CommitGate's Git hook, 4-rule deterministic verifier, SQLite WAL state store, and live SSE HUD widget.

Snapshot Commit: a3f873a

1. Plain-Language Overview

CommitGate proves local developer work happened using deterministic rules rather than self-reported checkboxes or vibes-based AI grading. It has four main pieces:

  • CLI Controller (src/cli.ts): Starts, inspects, cancels, and resets focus sessions in SQLite.
  • Git Post-Commit Hook & Verifier (src/hook.ts & src/verifier.ts): Fires automatically on every git commit and checks 4 deterministic rules (token match, required glob path modified, non-whitespace code diff, and passing test command).
  • SQLite State Store (src/db.ts): Persists sessions and commit_attempts in commitgate.db (WAL mode) and exposes PRAGMA data_version digests.
  • Local SSE HUD Server & Widget (src/server.ts & src/public/index.html): Watches SQLite state every 250ms and streams Server-Sent Events to the 360px monospace HUD card.

3. Reference Code Route (3 Stops)

Reference route tracing a commit from the Git hook through deterministic verification to live SSE broadcast:

Stop 1: Automatic Hook Entrypoint — src/hook.ts
Symbol anchor: export function runPostCommitHook

Checks getActiveSession(). If no session is PENDING, records the commit as UNTRACKED and prints CommitGate: no active session. Commit ignored. Otherwise delegates to the deterministic verifier and prints the terminal report.

Stop 2: 4-Rule Deterministic Engine — src/verifier.ts
Symbol anchors: export function evaluateLatestCommit & export function matchesRequireGlob

Inspects HEAD via Git commands to evaluate Rule 1 (token in commit message), Rule 2 (changed path matches --require glob), Rule 3 (non-whitespace lines changed > 0), and Rule 4 (--test command exits 0, capturing the last 5 lines on failure).

Stop 3: SQLite Digest & SSE Broadcast — src/db.ts & src/server.ts
Symbol anchors: export function getStateDigest (src/db.ts) & export function startHudServer (src/server.ts)

Combines SQLite's PRAGMA data_version with session/attempt metadata so the long-running HTTP server detects writes from separate CLI or Git hook processes within 250ms and pushes data: <json> over GET /events to src/public/index.html.

4. "To Change This, Start Here" Pointers

Add a 5th deterministic verification rule (e.g., minimum lines changed or branch name check)

Start in src/db.ts (interface RuleBreakdown), compute the rule inside src/verifier.ts > evaluateLatestCommit, and add the row to formatVerificationReport and src/public/index.html > renderSnapshot.

Customize the 360px HUD card layout, colors, or typography

Edit the CSS variables (--bg, --card, --pending, --rejected, --verified) and card markup directly in src/public/index.html. No frontend build step is required—just refresh http://localhost:4321.

Layer LLM feedback after deterministic pass/fail ("Later" roadmap)

Hook into src/hook.ts > runPostCommitHook after recordVerificationAttempt() completes. Pass the deterministic evaluation.rules JSON to your LLM helper so the model explains the result without ever controlling the pass/fail state.

5. A Practice to Reuse

Decouple Short-Lived Hooks from Long-Running UIs via SQLite `PRAGMA data_version`

In spec.md > Decisions and Open Issues and src/db.ts > getStateDigest, instead of having the Git post-commit hook make network calls to the HUD server (which can fail or block commits if the server is down), the hook writes strictly to local SQLite in WAL mode while the SSE server monitors PRAGMA data_version. Reuse this pattern whenever CLI tools, Git hooks, or background agents need to share live state with a local UI without fragile IPC sockets.
